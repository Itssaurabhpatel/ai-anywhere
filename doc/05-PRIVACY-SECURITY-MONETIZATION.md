## 1. Privacy Architecture & Data Protection

Privacy is a non-negotiable core architecture requirement for **AI Everywhere**. Because a keyboard processes sensitive personal and workplace communications, data protection is engineered directly into the client pipeline.

```
+-----------------------------------------------------------------------------------+
|                        CLIENT-SIDE PRIVACY SANITIZATION PIPELINE                  |
+-----------------------------------------------------------------------------------+
| Raw User Input (Keyboard / Text Field Buffer)                                     |
|                                                                                   |
|    ↓ [ Step 1: Sensitive Input Field Filter ]                                    |
|    - Is Password / OTP / Credit Card Field?                                       |
|      ➜ YES: ABORT IMMEDIATELY (AI Engine Disables Itself)                         |
|                                                                                   |
|    ↓ [ Step 2: On-Device PII Regex Masking ]                                     |
|    - Phone Numbers:  (\+?\d{1,3}[-.\s]?)?\d{10}  ➔ [PHONE_NUMBER_REDACTED]          |
|    - Emails:         [A-Za-z0-9._%+-]+@[...]     ➔ [EMAIL_REDACTED]                 |
|    - Credit Cards:   4[0-9]{12}(?:[0-9]{3})?     ➔ [CARD_REDACTED]                  |
|    - SSN / Aadhaar:  \d{4}\s\d{4}\s\d{4}        ➔ [GOVT_ID_REDACTED]               |
|                                                                                   |
|    ↓ [ Step 3: Zero-Retention Transit Engine ]                                    |
|    - Transmitted via TLS 1.3 encrypted gRPC connection                            |
|    - Processed in-memory by backend AI orchestrator                               |
|    - ZERO server-side logging of raw message content                              |
|    - Response returned ➔ Client preview rendered ➔ Volatile memory purged         |
+-----------------------------------------------------------------------------------+
```

### Data Storage Policy Matrix

| Data Type | Stored On Device? | Stored On Backend? | Retention Window | User Deletion Control |
| :--- | :--- | :--- | :--- | :--- |
| **Typed Message Content** | ❌ Never | ❌ Never | `0 Seconds` (In-Memory Only) | N/A |

## 2. Content Safety & Guardrail Architecture

To prevent accidental generation of harmful, offensive, or financially damaging text:

1. **Pre-Processing Financial & Password Safeguards**: Any text string containing patterns resembling credit card CVVs, bank PINs, or standard 6-digit OTP codes triggers an immediate client-side block.
2. **Safety Classifier Layer**: Output generated by LLM models passes through a lightweight safety filter before rendering in the keyboard preview card.
3. **User-in-the-Loop Safeguard**: AI Everywhere *never* automatically sends or submits text. The user must manually review and tap `Insert`.

## 5. App Store & Google Play Store Policy Playbook

To ensure friction-free approval on the **Apple App Store** and **Google Play Store**:

### iOS App Store Compliance (Guideline 2.5.4 & 5.1.2)
1. **Full Access Explanation**: Provide clear onboarding copy explaining that "Full Access" is required solely to communicate with cloud AI servers for generating responses, not to log keystrokes.
2. **Restore Purchases**: Include a visible, functional `Restore Purchase` button on the paywall screen.
3. **Sandboxing**: Strictly ensure the keyboard process never accesses data outside its designated App Group container.

### Google Play Store Compliance (User Data & Accessibility Policy)
1. **Accessibility Policy**: AI Everywhere does **NOT** require `AccessibilityService` for core operations. It relies strictly on standard IME APIs, clipboard context, and Intent share sheets.
2. **Prominent Privacy Disclosure**: Display an explicit privacy modal during onboarding requiring user agreement before enabling the keyboard input service.
